# API Reference

Base URL: `http://127.0.0.1:8000` (dev)

## Auth

Two headers, checked by dependencies in `app/middleware/auth.py`:

| Header | Required | Behavior |
|---|---|---|
| `x-api-key` | Only on routes listed below | Must equal `AADRIK_API_KEY`. **If `AADRIK_API_KEY` is unset on the backend, this check is skipped entirely** — a warning is logged at startup. Never deploy without setting it. |
| `x-user-id` | On chat/session routes | Free-form string generated per-browser by the frontend (`frontend/src/utils/userId.js`). Not an authenticated identity — just a way to scope chat history. Missing header → `400`. |

`x-api-key` is currently enforced on `/chat`, `/products`, and `/sessions*` only. `/quotation*`, `/crm*`, and `/knowledge*` have no auth dependency yet (see [ARCHITECTURE.md](ARCHITECTURE.md#known-gaps-pre-phase-1)).

## Chat

### `POST /chat`
Auth: `x-api-key`, `x-user-id`

Request body:
```json
{ "message": "string (1-2000 chars)", "session_id": "string | null" }
```
Response:
```json
{ "reply": "string", "sources": ["string"], "session_id": "string" }
```
Runs retrieval against the knowledge base, sends the result + conversation history to the LM Studio chat model, and persists both the user message and the reply. Creates a new session if `session_id` is omitted or unknown.

Errors: `503` if the knowledge base / vector store is unavailable, `504`/`502` if LM Studio can't be reached or times out.

## Sessions

### `GET /sessions`
Auth: `x-api-key`, `x-user-id`
Returns all chat sessions for the calling `x-user-id`: `[{ id, title, updated_at }]`.

### `GET /sessions/{session_id}/messages`
Auth: `x-api-key`, `x-user-id`
Returns `{ session_id, title, messages: [{ role, content, sources }] }`. `404` if the session doesn't exist or doesn't belong to this `x-user-id`.

---

## Products

### `GET /products`
Auth: `x-api-key`
Returns the full catalog from `data/products.json` (cached in-process): `{ categories, brands, products: [...] }`.

## Quotations

### `POST /quotation/`
Request body (`QuotationRequest`):
```json
{
  "company_name": "string", "contact_person": "string", "phone": "string",
  "email": "string | null",
  "product_name": "string", "brand": "string | null", "size": "string | null",
  "quantity": "string",
  "delivery_city": "string", "pincode": "string",
  "gst_number": "string | null"
}
```
Response: `{ success, quotation_id, message }`. Creates a row in `quotations` with `status = "New"` — this is also how a lead enters the CRM.

### `GET /quotation/{quotation_id}/pdf`
Streams a branded PDF quotation (`application/pdf`) generated by `app/services/quotation_pdf.py`. Pricing fields are placeholders (`-`) — the AI is explicitly forbidden from stating prices; a human fills them in outside the system today.

### `GET /quotation/all`
Returns every quotation row, newest first.

### `PUT /quotation/{quotation_id}/status`
Body: `{ "status": "string" }` (query or body per FastAPI's default param binding — passed as `status: str`). Updates the row's status. `404` if not found.

### `DELETE /quotation/{quotation_id}`
Deletes the quotation row. `404` if not found.

### `GET /quotation/customers`
Returns quotations grouped by `company_name` with aggregate counts: `[{ company_name, contact_person, phone, delivery_city, total_quotations, last_quotation }]`.

## CRM

`/crm/*` reads/writes the same `quotations` table as `/quotation/*` — see [ARCHITECTURE.md](ARCHITECTURE.md#data-model-sqlite-backenddatabaseappdb).

### `GET /crm/leads`
All quotations, newest first (same shape as `GET /quotation/all`).

### `PUT /crm/leads/{lead_id}`
Query param `status: str`. Updates the lead's status. `404` if not found.

---

## Knowledge

Both endpoints parse a markdown file from `knowledge_base/` into `[{ title, body }]` by `#`/`##` headers, skipping any section titled "AI Assistant Guidance" / "AI Assistant Knowledge" (those sections are for the chat model only, not for display).

### `GET /knowledge/policies`
Parses `knowledge_base/policies.md`.

### `GET /knowledge/company`
Parses `knowledge_base/company.md`.
